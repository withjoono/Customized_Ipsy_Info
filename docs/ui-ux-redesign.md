# UI·UX 재구성 — 2026-09-14

## 확인한 문제
- 배포된 첫 화면은 제목·설명·로그인 버튼만 제공하여, 로그인 전에 핵심 기능인 입시 캘린더를 발견하기 어려웠다.
- 작업 중인 프론트는 최대 폭 720px의 단일 열 구조여서 데스크톱 공간을 충분히 활용하지 못했다.
- 작은 본문, 반복되는 보라색 버튼, 약한 내비게이션 상태 표시로 정보와 행동의 우선순위가 흐렸다.
- 공개 API가 HTML을 반환하면 배열 처리 중 화면 오류가 발생할 수 있었다.
- 구독 조회 중/실패/미설정을 구분하지 않아 실제 상태와 다르게 보이거나 빈 설정을 저장할 수 있었다.

## 적용한 방향
- 블루 입시 캘린더를 최상단 주요 영역으로 유지하고, 맞춤 피드 → 구독 순서를 보존했다.
- 데스크톱은 안내와 달력의 2열 배치, 모바일은 1열 배치를 적용했다.
- 비로그인 방문자에게 실제 공개 캘린더를 제공한다. 월 이동·오늘 이동·날짜 선택과 전체 일정 이동이 가능하다. 예시 일정을 실제 일정으로 표시하지 않는다.
- 내비게이션 활성 상태, 키보드 초점, 본문 바로가기, 필터 선택 상태를 개선했다.
- 공개 일정·맞춤 피드·구독 화면에 동일한 글자·여백·카드·폼 규칙을 적용했다.
- 고1·고2 준비 모드, 고3·재수생 실행 모드 및 Hub 인증 흐름을 유지했다.
- 공개 일정 응답 검증 및 조회 오류/로딩/빈 상태 안내를 보강했다.

## 검증과 범위
- npm run typecheck 통과.
- 세 Vite 환경변수를 로컬 주소로 명시한 npm run build 통과.
- 3012 로컬 미리보기 HTTP 200 확인.
- 로그인 세션을 사용한 개인화 데이터·구독 저장 통합 검증과 브라우저 반응형 동작 검증은 수행하지 않았다.
- 운영 배포는 수행하지 않았다. 생성한 dist는 로컬 주소를 포함한 검증용이므로 운영에 배포하지 말 것. 배포 시 확정된 운영 환경변수를 사용해 다시 빌드해야 한다.
- 기존 사용자 변경 및 백엔드·DB는 이번 작업에서 수정하지 않았다.

## 운영 배포 준비
- 운영 공개 주소만 담은 .env.production을 추가하고 운영 설정 빌드를 통과했다.
- 운영 infocast-backend 서비스 존재를 확인했으나 /api/public/calendar는 404를 반환했다. 공개 일정 API 반영은 별도 백엔드 작업이 필요하다.
- 프론트 코드와 화면에 필요한 기존 캘린더 구성요소를 함께 배포 대상으로 포함한다. 백엔드 작업 트리는 유지한다.
